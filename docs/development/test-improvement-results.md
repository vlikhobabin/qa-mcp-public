# Результаты T0–T5: тесты qa-mcp

Дата: 2026-09-10. [План](test-improvement-plan.md) выполнен в согласованных
границах. Изменены тесты, их вспомогательные данные, карта выбора и документация.
Код продукта, Windows host-agent, ChangeRail и сохранённый payload FIX-02
не изменялись. Коммит и публикация в рамках этой работы не выполнялись.

После T0–T5, при подготовке оркестратора OSS-00, четыре проверки с настоящими
Git/pytest subprocess перенесены из `test_test_selection.py` в отдельный
integration-файл. Пять чистых проверок остались offline; общий builder вынесен
в `tests/support/selection_inputs.py`. Новая подчинённая Codex-сессия проверила
только эти файлы: **5 passed / 0,10 с** и **4 passed / 1,91 с** соответственно.
Это отдельный малый фикс; измерения T0–T5 ниже сохранены исторически. Текущий
состав — **1631 случай: 1617 offline и 14 integration**, без новых случаев.
Доказательства: `.runtime/oss00-orchestrator-preparation-20260910/selector-lane-fix/`.
Первый сбор нового инвентаря выявил имя helper `test_selection.py`, которое
попадало под шаблон тестовых модулей без собственных случаев. Helper переименован
в `selection_inputs.py`; после обновления импортов повторены только эти два файла:
**5 passed / 0,09 с** и **4 passed / 2,04 с**. Новый инвентарь собран без исполнения.
Первичные логи, повторные `*-final` результаты и исходная попытка collection сохранены.

## Достоверность проверок

`test_bootstrap_platform_selection.py` больше не реализует выбор версии на Python.
Он проверяет объявленную политику direct capture/fallback и присутствие связей
в исходнике bootstrap. Такие assertions не доказывают исполнение веток Windows:
это явно указано в docstring и именах тестов. Сам bootstrap не удалён: у него
есть потребители в тестах доставки и шаблоне поддержки платформ.

`test_multi_version_delivery_docs.py` читает `platform_version` из явно названных
`config/protocol-capture-manifest-8.3.json` и `...-8.5.json`. Наличие новой папки
bundle не объявляет новую платформу поддержанной. Сохранены `/mcp`, имена
runtime-параметров и конкретный путь bundle; удалены два поиска отдельных слов
прозы, которые не доказывали смысл инструкции. Поддержка платформ этим тестом
по-прежнему не квалифицируется.

Два локальных отрицательных контроля подтвердили, что неверное direct-семейство
и устаревшая версия в документации вызывают AssertionError. Менялись только
значения в памяти; исходники bootstrap и документации доставки не менялись.

## Подготовка и изоляция

`TargetProfileInputs` хранит неизменяемые параметры; каждый вызов выдаёт новые
profile/env словари и независимые вложенные fingerprint-проекции. Запись JSON
отделена от создания физических файлов. Контексты, session, attachment, ledger
и каталоги остаются отдельными для каждого случая. Resolver вызывается реально;
запись файлов сохранена в проверках физических путей, evidence и публичных маршрутов.

Минимальный контекст чистого валидатора уже не создавал файлов: заменять его
кэшем не потребовалось. Отличающиеся Settings/endpoint и generation=7 остаются
явными в соответствующих фикстурах; общий набор скрытых mutable defaults не введён.
Lifecycle-построитель из остановленного FIX-02 не мигрирован: он был дополнительным
кандидатом, его файл сохранён побайтно. Три основных потребителя мигрированы.

Исходный замер обнаружил прежний сбой
`test_bound_nonowned_cleanup_detaches_without_signal`: setup вызывал публичный
attach, который текущий runtime уже отклоняет без observation target. До очистки
attachment не возникал. Теперь тест задаёт ранее допущенную неприсвоенную сессию
и проверяет именно detach без сигнала процессу, очистку session и attachment.
Запрет публичного attach не обходится в продукте и его тесты не ослаблены.

## Решения по матрицам и повторам

| Группа | Владелец и доказательство | Решение |
| --- | --- | --- |
| 408 core cases | Валидатор: literal/type/domain, URL, limits, provenance и evidence receipts | Сохранить: вся группа требует менее секунды непосредственного исполнения |
| 132 encoded-control + 66 raw-control cases внутри core | Различные символы и стадии разбора URL; decoded и raw входы попадают в разные условия | Сохранить; разные воздействия parser/decoder, не один повторённый вход |
| 20 core URL cases и 40 public URL cases | Чистая нормализация против реальных MCP/ScenarioRunner вызовов; точные 40 закреплены spec | Общий построитель входов, обе матрицы сохранены |
| 30 public admission refusals | 15 состояний × Local/Windows executor; до вызова адаптера нет эффекта | Сохранить обе ветви |
| 8 public verdict/provenance cases | Четыре verdict × два маршрута | Сохранить таксономию и сериализованную identity |
| 12 public mismatch cases | По шести неверным значениям на обоих маршрутах | Сохранить проверку реального пути |
| 12 structural + 2 final-byte public cases | Below/exact/above значения; точные размеры сериализованного результата | Сохранить граничный oracle и прохождение обоих маршрутов |
| Scope/concurrency, identity drift, compatibility и сценарные adapters | Области evidence, снимок identity и путь ScenarioRunner имеют отдельные обязательства | Сохранить; injected executor не заменяет ещё не исправленные default BDD пути |
| Семь совпадений тел вложенных fake/handler функций | Замыкания и подменяемые владельцы различаются | Оставить локальными; одинаковое тело не доказывает взаимозаменяемость |

Сравнение AST подтвердило неизменность всех 42 core и 14 public test-функций,
включая decorators/параметризацию: сохранены все **524 случая**. Перенесены только
их чистые helpers и подготовка profile. Не найдено обоснования удалять сценарии
ради скорости. Изменение полноты обязательных матриц не входило в поручение.

11 перенесённых проверок: восемь source/render/config проверок доставки и три
PE/provenance проверки с синтетическими файлами. Они расположены в
`tests/test_self_hosted_release_contract.py` и
`tests/test_windows_host_agent_artifact_contract.py`. Shell syntax check сохранён
в integration, поскольку выполняет subprocess. Подтверждена неизменность всех
11 тел и выбор новых файлов соответствующими исходными зависимостями.

## Проверки и время

Числа ниже — один исходный и один итоговый замер на одном Linux-хосте.
Время команды включает запуск uv/Python/pytest; колонка pytest — длительность
из итоговой строки pytest. Это разные интервалы, их нельзя подменять друг другом.

| --- | --- | --- |
| Bootstrap + docs | 5 passed / 0,08 с / 2,98 с | 5 passed / 0,10 с / 2,87 с |
| Boundary + cleanup | 548 passed, 1 failed / 17,07 с / 21,89 с | 550 passed / 17,50 с / 22,42 с, включая новый контроль изоляции |

| Перенесённые offline + archive + selector | Составная новая группа | 25 passed / 2,45 с / 5,66 с |

Последняя группа состоит из 11 перенесённых случаев, пяти archive и девяти
проверок выбора. Вместе с остальными итоговыми пакетами успешно проверены
**587 различных случаев**. Полного прогона не было. Инвентарь собрал 1631 случай
без исполнения, с пустым списком runtime reports.

| Группа | setup до → после | call до → после | teardown до → после |
| --- | --- | --- | --- |
| 408 core cases | 0,164 → 0,165 с | 0,461 → 0,459 с | 0,073 → 0,074 с |
| 116 public cases | 0,118 → 0,121 с | 8,270 → 8,319 с | 0,027 → 0,028 с |
| 25 cleanup cases | 0,026 → 0,027 с | 5,174 → 5,271 с | 0,009 → 0,007 с |

Создание профиля находится внутри test call, поэтому его стоимость не следует
искать только в pytest setup. Наибольшие отдельные длительности — публичный
MCP путь с созданием сервера и byte-boundary тест, делающий несколько реальных
вызовов. Перенос построителей **не показал ускорения** этой группы: выигрыш здесь
в сопровождении и изоляции, а не в скорости. Процент ускорения не заявляется.

В integration до и после выполнялась одна настоящая сборка host-agent через
существующую session fixture. Setup занял 2,12 и 1,11 с; cache не очищался,
повторная сборка могла воспользоваться Go cache. Разницу нельзя приписать
рефакторингу. Неизменённый тест воспроизводимости с двумя сборками сохранён
и явно исключён из обоих замеров. Windows executable не запускался.

## Сохранённые попытки и ограничения

Локальные материалы находятся в `.runtime/test-improvement/`:
`initial-files.json`, `before/`, `<пакет>/<попытка>/run.json`, `pytest.log`,
`junit.xml`, `phases.json`, а также T1 negative controls, T4 карта переносов,
проверка зависимостей/сохранности и T5 collection. Хеши и команды привязаны
к каждой попытке; времена collection включают инициализацию pytest после
подключения локального измерителя. Это не отдельный микро-бенчмарк collector.

Сохранены два неуспешных прогона: исходный cleanup-сбой и промежуточный T2
с четырьмя NameError после удаления ещё используемого импорта `quote`.
Импорт восстановлен, четыре случая прошли точечно, затем вся затронутая
boundary-группа прошла после финальной миграции. Попытки не удалялись.

Live 1С/Windows проверки, полный coverage floor и тесты ChangeRail не запускались.
Классификация Go остаётся прежней: 200 функций, из них 34 Windows-only; это не
34 доказанных live 1С запуска. Native bootstrap execution и недоступные captures
остаются явно непроверенными, а не превращаются в successful proof.

Декомпозиция `mcp_server.py`, новый Windows harness и исправления default BDD
из OSS-FIX-09a/b/c остаются отдельной продуктовой работой. Выполнение этого
плана не закрывает эти карточки и не возобновляет остановленную дорожную карту.
