# Результаты переноса локального ChangeRail

Дата: 2026-09-05. Основание: согласованный межкомпонентный план
`qa-mcp-local-changerail-astra-migration-plan.md` и запрос выполнить его.
Ниже сохранены результаты исходного offline-переноса до синхронизации.
Последующая сверка с опубликованным upstream описана в
[правилах перехода](legacy-board-transition.md). Пилот не запущен.
Этот отчёт не является независимым publish GO продуктовой карточки.

## Что перенесено

Исходный meta-mcp: `69ad52f57607e3e1cc60f234b230edcd5fd49c9f`;
последнее изменение механизма: `3d9828ef3ecd59eee29fc1760cb83d234f4a9858`.
Происхождение, лицензия и точные хеши 20 исходных файлов сохранены в
`tools/changerail/{ORIGIN.md,LICENSE,upstream-snapshot.json}`.
Код, профиль, схемы и workflow skills теперь принадлежат qa-mcp и не требуют
checkout meta-mcp или /opt/changerail. Исходный механизм не изменялся.

Сохранены четыре стадии FF, Change checkpoints, fingerprint-bound evidence и
verdict, handoff, независимое ревью, ограниченные repair lanes и recovery.
FF/review переведены на `gpt-6-astra/high`, реализация/repair оставлены на
`gpt-5.6-terra/high`. Исходные бюджеты не менялись. Новые локальные schema IDs
имеют префикс `qa-mcp.*`; замороженные wire IDs `ai1c.*` не переименованы.

QA-gates используют non-live pytest с coverage >=60%, compilation и строгие
canonical specs. Удалены обязательный PostgreSQL preflight и Metadata inventory
guard; добавлена явная dev-зависимость jsonschema. Go/Windows и runtime evidence
по-прежнему выбираются по затронутому поведению и требуют соответствующего
разрешения. Отслеживаемый `.codex/config.toml` теперь входит в fingerprint;
runtime/auth/session state исключены.

`chrl install` установил локальный `core.hooksPath=scripts/git-hooks`.
34 старые внешние ссылки заменены/удалены; их исходные цели сохранены в
`.runtime/changerail/migration/replaced-links.json` и доступны в Git history.
Сами внешние файлы не удалялись. Локальные Codex/Claude workflows сохранены
вместе с проектными и доменными skills. `board-do --exec` теперь отказывает до
мутации; обычный helper нужен runner для перехода карточки. `chrl-run` включает
commit/push: `require_push=false` не является запретом публикации.

## Astra и инструкции

Использован предоставленный пользователем текст
[Using GPT-6 Astra](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md)
после HTTP 403 официального источника. OpenAI Docs определил проверки
совместимости и сохранение reasoning/ролевой маршрутизации. Skill Creator
использован для уточнения границ skills и проверки их поведения.

В AGENTS.md и навыках уточнены автономность в разрешённой области, приоритет
пользовательского задания, объяснение остановок из-за skills, краткий стиль,
соразмерные проверки и ограниченное делегирование. Обычная offline-правка
завершается проверками и отчётом, без искусственного требования runner handoff.
Измеряемые роли сохраняют обязательные verdict/handoff и не публикуют сами.
Датированный лабораторный контекст вынесен в отдельный документ без потери
runtime/preflight/recovery ограничений. Root AGENTS явно допускает локальный
board-only процесс этого компонента.

Проверенный CLI: `codex-cli 0.153.4`, machine provider `codex-lb`,
`wire_api=responses`. Проверенные top-level настройки не содержали запрещённых
sampling/logprobs параметров. Launcher явно передаёт модель/reasoning: локальный
pool иначе подставлял Sol. Runtime config материализуется приватным обычным
файлом, поскольку ссылка на project config заставляла pool сбрасывать CODEX_HOME
и терять локальные skills. Авторизация и настройки proxy не переносились в Git.
Успешны минимальный ответ модели и Responses tool roundtrip. Запрошенная CLI
маршрутизация не доказывает внутреннюю модель провайдера; EU residency и
параметры невидимых upstream запросов этим не сертифицированы.

Полный QA-прогон был до финальных небольших исправлений launcher, helpers и
классификации QA pytest floor. После них прошли все 119 целевых тестов; полный
набор повторно не запускался. Он проверяет текущий dirty checkout вместе с
существовавшей продуктовой работой и не доказывает её отдельную готовность.
Новых live/Windows прогонов и проверки реальной карточки не было.

Одинаковые шесть изолированных сценариев проверили plan-only, обычную offline
правку, полный перечень review findings, stale evidence, checkpoint recovery и
отдельное согласование пилота. Модель читала fixture через shell tool в
read-only временном workspace. Это проверка решений по инструкциям, а не
полный многоходовый FF/delivery или доказательство качества всех сценариев.
Admission/decomposition и механические recovery gates покрыты тестами harness.

| Набор инструкций | Сценарии | Время | Input / cached / output tokens | Shell commands |
| --- | --- | --- | --- | --- |
| Восстановленный baseline до оптимизации | 6/6 | 27,66 s | 29460 / 11264 / 269 | 1 |
| Адаптированные инструкции, attempt-2 | 6/6 | 28,12 s | 32676 / 13056 / 265 | 1 |

Первый adapted запуск завершился на старте до model events за 61,67 s;
usage неизвестен. Он сохранён отдельно, успешная попытка его не перезаписывает.
Один небольшой замер не показывает улучшения стоимости или скорости;
бюджеты оставлены прежними. Baseline реконструирован из закреплённых source
skills и прежнего QA AGENTS с локальной workflow-адаптацией.
Независимый read-only просмотр инструкций также выполнен; это не publish gate.

Результаты и хеши входных инструкций находятся в ignored
`.runtime/changerail/migration/instruction-evals/`; состав собственных изменений
и итоговые хеши — в `payload-manifest.json` той же migration-директории.
Runtime evidence не предназначены для автоматического добавления в Git.

## Состояние до последующей сверки Git

В checkout сохранена незавершённая продуктовая работа и несколько активных
карточек. Локальный main отстаёт от известного origin/main на 21 commit;
fetch/pull не выполнялись. Doctor ожидаемо отказывает по dirty-start, неполному
новому admission старой карточки и нескольким active cards; wiring, история
и маршруты проходят. Нельзя объявлять это recovery нового runner.

[Legacy transition](legacy-board-transition.md) сопоставляет три незавершённых
change-каталога с карточками и оставшимся планом. Их подробные tasks/design
сохранены на прежних путях, без изменения галочек и принятия старых карточек.
Согласование конкретной продолжаемой работы, перенос её оставшихся шагов в
admission-ready карточки и reconciliation ветки остаются перед активацией.
Snapshot включает прежние untracked legacy artifacts; миграционный commit сам
по себе не обеспечит их наличие в чистом clone. Нельзя молча включать чужую
работу в публикацию или ослаблять snapshot для прохождения doctor.

Перенос выполнен вручную как bootstrap по явному плану пользователя, а не
доставлен собственной карточкой нового runner: объём копии превышает admission
budget, checkout уже занят. Никакой фиктивный GO/статус done не создавался.

Пилот остаётся отдельным этапом. После reconciliation сначала подготовить
конкретную небольшую карточку, команду, модели/бюджеты, побочные эффекты
(включая commit/push), evidence и условия остановки; затем согласовать запуск
с пользователем. До этого состояние: **перенос проверен, пилот не запущен**.

## Последующая проверка и сверка, 2026-09-05

Независимая проверка исходного checkout подтвердила все 80 путей локального
манифеста, 20 исходных хешей и 119 тестов механизма. Полный повторный non-live
прогон после последних исправлений дал 1773 passed и coverage 75,10%.

Этап 6 остаётся частично подтверждённым в части поведения Astra: шесть
сценариев проверяют выбор действия по инструкциям, а не фактическую работу FF,
полного NO-GO и прерывания с восстановлением. Ускорение или снижение стоимости
не доказаны. Изолированные поведенческие прогоны остаются отдельной проверкой;
они не заменяются и не разрешаются автоматически реальным пилотом.

После разрешения пользователя подготовить коммиты и push незавершённая работа
сохранена отдельными локальными checkpoint-коммитами `350fddb` и `faecfc2`.
Main синхронизирован с опубликованным `8e94a21`; перенос применяется поверх него
без восстановления прежней продуктовой реализации. Сохранены публичные README,
Apache-2.0 metadata, ограничения I16 и fail-closed public-readiness gates.
Три точных email-fixture в домене `example.invalid` для изолированных Git-тестов
включены в пофайловый счётный allowlist; широких исключений сканера не добавлено.

Сверенный legacy-снимок содержит только 1419 опубликованных файлов. Прежние
локальные артефакты доступны в архивной ветке, а их отношение к текущему
upstream зафиксировано явно. До активации runner остаются инвентаризация
незавершённых карточек, принятие оставшихся планов и согласование пилота.

Проверки синхронизированного payload: 70 canonical specs, public audit без
findings, provenance 649/649, 12 документов без битых ссылок и неизменённый
I2 с 23/23 негативными сценариями прошли. Полный non-live запуск дал 1728
passed и один сбой старого теста, ожидавшего 34 внешние workflow-ссылки;
coverage 74,67%. После обновления ожидания на пять локальных ссылок два
целевых snapshot-теста прошли: изолированный install/import/build/public audit
и сохранность локального workflow со всеми замороженными файлами. Полный
набор после этой тестовой правки не повторялся; продуктовый код не изменялся.

Отдельный Git-export checkout из staged tree `439a19c` прошёл locked offline
установку, local hook install/wiring, 70 спецификаций и восемь целевых тестов
истории/launcher. В нём отсутствует прежнее ignored-состояние и архивная ветка.
Компиляция, shell-синтаксис и whitespace также прошли. В публикуемом diff нет
изменений `src/`, Windows host-agent, lifecycle-артефактов и протокольного
evidence; live/native certification не заявляется.
