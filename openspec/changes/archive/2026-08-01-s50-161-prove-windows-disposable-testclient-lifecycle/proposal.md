## Why

Even with honest launch classification, root S50 remains blocked until the
extension-bearing disposable infobase follows a supported Windows staging path
and qa-mcp proves the own catalog through one owned TestClient lifecycle.

## What Changes

- Use a Windows-created disposable file infobase restored from a portable
  backup of the retained Linux extension-deploy proof, rather than treating a
  raw copied live 1CD directory as the acceptance path.
- Launch the restored infobase through `launch_test_client` on the authorized
  `HISTORICAL-LAB-HOST` host and retain the owned lifecycle target.
- Open `Справочник.S50ProofItems`, create one uniquely named disposable item,
  read it back from the catalog UI, and retain ignored screenshot evidence.
- Retain before/after inventory and remove only the exact run-owned stage,
  transient scheduled tasks, host-agent/TestClient processes, tunnels, and
  proof ports.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `qa-mcp-windows-host-agent-security`: define the accepted disposable
  file-infobase staging and exact-owned cleanup evidence boundary for Windows
  TestClient launch proof.
- `qa-mcp-tool-endpoint-contract`: require the S50 remote launch result to yield
  a usable owned lifecycle target for the first protocol/UI operation.

## Impact

- Ignored runtime evidence and the durable Windows TestClient launch/security
  contracts; Python/Go source changes are limited to defects discovered by the
  preceding classification change.
- Requires live 1C runtime on `User@192.0.2.200`, a disposable Windows-created
  infobase, and one reversible test-item mutation. It does not use Vanessa MCP,
  EDT/meta snapshots, customer data, or raw protocol capture.
