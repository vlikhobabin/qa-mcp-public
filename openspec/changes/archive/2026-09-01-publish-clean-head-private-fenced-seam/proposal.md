## Why

Published I5 Outcome A authorizes one bounded clean-HEAD successor to supply
the private fenced observation dependency that blocks later I4 work. The seam
must be independently compilable, connected at both existing worker inventory
boundaries and hostile-verified without absorbing predecessor or live-runtime
scope.

## What Changes

- Add private liveness, inventory, fenced-sample and pre-receipt diagnostic
  state with fail-closed validation and privacy-safe status mapping.
- Add the Windows process/job/TPort fence wrapper and connect it at exactly the
  two existing inventory boundaries in `observeHiddenDirectInWorker`.
- Add transferred-observer validation and a callback hold after acknowledgement
  while the existing local job/TPort ownership remains live.
- Add offline hostile coverage and curated RED/GREEN, staged-tree, scope and
  cross-build evidence for the exact seven-path authorized tree.
- Preserve all public, wire, marker, classifier, mutation, retry, fallback,
  S5, S7, fixture, OSS-07/08 and live behavior unchanged.

## Capabilities

### New Capabilities

- `qa-mcp-private-fenced-seam`: Private connected liveness/inventory fencing,
  diagnostic ownership and transferred-observer hold behavior authorized by
  the I5 publication decision.

### Modified Capabilities

- None.

## Impact

Only the seven existing Go paths named by the card, one new private capability
spec and card-owned privacy-safe evidence are affected. There is no API, wire,
route, package, module, dependency, target, runtime-lab or MCP-provider change.
Verification is offline and uses Go/Linux checks plus deterministic Windows
test cross-builds; it requires no live 1C, Vanessa MCP, EDT/meta snapshot,
endpoint, target access or Windows configuration mutation.
