## Why

Published S3 can isolate and select exact hidden-desktop windows, but it
deliberately provides no marker or UIA observation. Before prompt admission can
be separated into S5, qa-mcp needs a dormant passive boundary that proves the
unchanged direct-`/Execute` main window, one caller-supplied marker hash and one
bounded structural UIA topology without acquiring action authority.

## What Changes

- Add a portable fail-closed observation policy for exact main-window identity,
  marker cardinality, structural UIA rows and sanitized receipts.
- Add a Windows-only passive UIA inventory that hashes names and structural
  properties in memory, enforces fixed bounds and invokes no UIA action pattern.
- Add hostile RED/GREEN tests and exact-source Windows direct-`/Execute`
  observation/cleanup evidence.
- Keep S1-S3 byte-identical, the primitive dormant and S5-S7/public behavior
  unchanged.

## Capabilities

### New Capabilities

- `qa-mcp-hidden-direct-execute-observation`: Exact hidden main-window,
  caller-supplied marker-hash and bounded sanitized UIA topology observation
  with zero action authority.

### Modified Capabilities

- None.

## Impact

The change adds separate dormant Go source/test files, one new capability spec,
OpenSpec/card records and ignored sanitized evidence. It does not touch protocol
tools, Python manager code, MCP provider setup/profile, runtime lab config or
published S1-S3. Offline Go verification is supplemented by one read-only live
Windows 1C run on exact platform `8.3.27.2214` and declared
`vanessa_client`; Vanessa MCP, EDT/meta snapshots and protocol capture/replay
are not required.
