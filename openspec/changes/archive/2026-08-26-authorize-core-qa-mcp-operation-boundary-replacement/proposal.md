## Why

OSS-04D-R5 is a repeated-defect implementation whose ordinary delivery cap is
300 added production lines. ChangeRail deterministic preflight must consume
its narrowly higher machine ceiling from one published, exact and reciprocal
authorization source rather than from roadmap prose or a reusable waiver.

## What Changes

- Publish one closed six-field investigation authorization object bound to the
  completed OSS-04D-R4-R1 investigation and exactly one OSS-04D-R5 successor.
- Make the R4-R1, A2 and R5 board relationships reciprocal and
  machine-readable while retaining R5's stricter 300-line implementation cap.
- Prove that a finalized exact candidate is accepted and that a bounded
  successor mismatch is rejected by deterministic preflight.
- Keep the payload metadata-only: no Python manager, MCP, protocol, runtime lab
  or Windows behavior changes.

## Capabilities

### New Capabilities

- `qa-mcp-core-operation-boundary-authorization`: Defines the exact published
  authorization source and reciprocal fail-closed consumption rules for the
  bounded OSS-04D-R5 core operation-boundary successor.

### Modified Capabilities

- None.

## Impact

The change affects only qa-mcp OpenSpec workflow and board metadata. It needs
no live 1C runtime, Vanessa MCP, EDT/meta snapshot, protocol capture, Windows
host, Docker or runtime cleanup.
