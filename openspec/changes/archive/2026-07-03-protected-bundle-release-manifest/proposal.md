## Why

The suite Docker architecture separates large provider data assets from code
images, but qa-mcp's encrypted `_bundled/` corpus is a small protected protocol
asset and must remain inside the protected image. The release contract needs to
make that exception explicit so future publish tooling does not split out the
protocol IP as a public data artifact.

## What Changes

- Ratify a qa-mcp-specific P5 carve-out: encrypted `_bundled/` remains baked into
  the protected code image.
- Extend the component release manifest generated by qa-mcp release tooling to
  declare the protected image asset and no separate `_bundled` data asset.
- Keep `docker/verify_protected_image.py` as the acceptance gate that proves the
  bundled data is encrypted and readable by the protected runtime.
- Update delivery docs with the carve-out and its residual risk.

## Capabilities

### New Capabilities
- `qa-mcp-protected-release-assets`: qa-mcp release manifests distinguish protected
  baked protocol assets from external data artifacts.

### Modified Capabilities
- none

## Impact

Touches delivery documentation, release manifest generation and protected-image
verification. It does not change protocol behavior, capture contents or live
1C runtime behavior. Evidence is image verification and manifest inspection.
