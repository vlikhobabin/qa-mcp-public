## Context

Published investigation OSS-07-R1-I1 found that the complete unpublished
OSS-07-R1 public-readiness payload crossed ChangeRail's default 300-line
production-complexity limit. It prepared the exact machine authorization data
for a later separate source, but intentionally did not create that source,
modify the successor or certify any successor byte, count or evidence claim.

ChangeRail admits the bounded ceiling only when the separate source is an
unchanged tracked `4.done` card, depends on the published investigation, and
contains exactly six machine fields. This metadata-only change supplies that
source and nothing from the absent successor payload.

There are no TestClient protocol claims, capture sources, frame ranges,
dynamic fields, replay steps or runtime cleanup obligations. No process,
service, credential, endpoint or execution target is used.

## Goals / Non-Goals

**Goals:**

- Publish the exact I1-prepared six-field authorization for exact OSS-07-R1.
- Bind one unchanged published I1 dependency and one exact successor id/path.
- Preserve the hard `350` complete-production-line ceiling and honest scope
  accounting without treating the ceiling as an implementation budget.
- Preserve all successor measurement, verification and semantic review as
  future admission work.
- Produce a metadata-only payload suitable for fresh independent review.

**Non-Goals:**

- Reading, importing, editing, measuring, reviewing, staging, certifying or
  publishing the OSS-07-R1 implementation payload or successor metadata.
- Restoring or reconstructing OSS-07-I1 or modifying published OSS-07-I2.
- Deleting whitespace, reclassifying production source or excluding owned
  scope to change the complexity result.
- Changing `Apache-2.0`, the global complexity gate, a public/wire contract,
  credential or mutation authority, or any runtime behavior.
- Running live, SSH, Windows, 1C, TestClient, Apache-service, credential,
  mutation, network, release, OSS-08 or OSS-09 work.

## Decisions

### 1. Preserve the exact six-field source object

The card and normative capability use the I1-prepared object unchanged:

```json
{"investigation_card":"openspec/board/4.done/oss-07-r1-i1-investigate-public-readiness-payload-complexity.md","investigation_id":"oss-07-r1-i1-investigate-public-readiness-payload-complexity","successor_card":"openspec/board/3.inprogress/oss-07-r1-replace-public-readiness-disclosure-and-evidence-integrity.md","successor_id":"oss-07-r1-replace-public-readiness-disclosure-and-evidence-integrity","production_loc_ceiling":350,"allow_new_authority_or_wire_protocol":false}
```

It has no optional field and is not reusable. The integer ceiling is a
conditional admission envelope for the exact named successor, not a current
measurement, an expansion budget, a payload certification or publication
approval.

### 2. Require the exact published investigation dependency

The authorization source depends on
`oss-07-r1-i1-investigate-public-readiness-payload-complexity` at its unchanged
tracked `4.done` path. That investigation's `Blocks` relation names exact
OSS-07-R1 at the authorization-time `3.inprogress` path. Another dependency,
path, id, ceiling, flag, lane or relation invalidates the source.

### 3. Keep successor composition and admission outside this payload

The successor is deliberately absent from this isolated worktree and is not
imported. Only a later fresh successor session may add its reciprocal I1
dependency and reference this exact unchanged tracked `4.done` source. That
session must measure the complete honest production scope at no more than 350,
retain its full verification evidence, pass deterministic preflight and obtain
a fresh independent semantic review.

No local statement about the successor implementation, size, blobs or tests is
accepted as proof. Above 350 lines, changed identity/scope, a new authority or
wire protocol, or any accounting workaround keeps admission fail-closed.

### 4. Preserve stable, complete complexity accounting

Whitespace deletion, production-source reclassification and owned-scope
exclusion are prohibited when used to evade the complexity gate. Blank-line
removal cannot substitute for simplification; production files cannot be
relabeled as tests, fixtures, docs, generated content or metadata; and
successor-owned production paths cannot be omitted from the manifest or
measurement.

### 5. Publish metadata only under the existing license boundary

The reviewed payload is limited to this board card, its OpenSpec authorization
artifacts, the synced capability and deterministic archive/publication
metadata. Exact SPDX `Apache-2.0` and published OSS-07-I2 remain unchanged,
OSS-07-I1 remains absent, and OSS-08/OSS-09 remain outside scope.

## Risks / Trade-offs

- [The ceiling is mistaken for successor certification] -> Keep all exact
  measurement, identity and verification proof in later successor admission.
- [The source is reused or broadened] -> Bind the exact six fields, sole I1
  dependency, reciprocal graph and `false` authority/wire flag.
- [Accounting changes create a false pass] -> Reject all three named
  complexity-gate workarounds and require the complete honest scope.
- [Metadata delivery imports implementation] -> Keep the successor absent and
  reconcile publication against an explicit metadata-only manifest.

## Migration Plan

1. Validate, sync and archive this metadata-only authorization change.
2. Obtain a fresh independent ordinary-risk GO for the exact scoped payload.
3. Publish the source unchanged and finalize its board card in `4.done`.
4. Leave successor composition, exact measurement, deterministic admission and
   semantic review to its separate isolated delivery session.

Rollback before publication removes no runtime behavior. After publication,
any substantive content change requires a newly reviewed payload; a missing,
changed, stale, untracked or mismatched source fails closed.
