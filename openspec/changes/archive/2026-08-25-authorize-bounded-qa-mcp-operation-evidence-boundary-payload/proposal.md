## Why

OSS-04D-R3 is a repeated-defect implementation whose reviewed typed boundary
may require up to 500 added production lines, above the ordinary ChangeRail
limit. Deterministic preflight must consume that exception from one published,
exactly reciprocal authorization source rather than from prose or a reusable
waiver.

## What Changes

- Publish one closed six-field investigation authorization object bound to the
  completed OSS-04D-R2 investigation and exactly one OSS-04D-R3 successor.
- Make the R2, A1 and R3 board relationships reciprocal and machine-readable.
- Prove in an isolated committed candidate tree that deterministic preflight
  accepts the exact successor and rejects mismatched reuse.
- Keep the payload authorization-only: no Python manager, MCP, protocol,
  runtime lab or Windows behavior changes.

## Capabilities

### New Capabilities

- `qa-mcp-operation-evidence-boundary-authorization`: Defines the exact
  published authorization source and reciprocal fail-closed consumption rules
  for OSS-04D-R3.

### Modified Capabilities

- None.

## Impact

The change affects only qa-mcp OpenSpec workflow, board metadata and durable
authorization documentation. It needs no live 1C runtime, Vanessa MCP,
EDT/meta snapshot, protocol capture, Windows host, Docker or runtime cleanup.
