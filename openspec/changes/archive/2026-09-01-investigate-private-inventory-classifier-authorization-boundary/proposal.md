## Why

Published I3/I6 select a bounded, behavior-neutral private classifier shape,
but exact I4's declared repeated defect class cannot use that prose lineage as
the reciprocal investigation/authorization graph required by ChangeRail. A
tracked decision is needed before a separate authorization source can bind
that exact successor without certifying unavailable local-payload claims or
granting a reusable waiver.

## What Changes

- Publish a decision that makes exact I4 the only conditionally eligible
  bounded simplification of the repeated inventory-diagnostic defect, limited
  to an at-most-five-path private classifier seam and mandatory hostile offline
  oracle.
- Bind the exact successor id and authorization-time `3.inprogress` path.
- Prepare the exact six-field JSON object for a later, separate authorization
  card using production ceiling `301` and no new authority/wire allowance.
- Preserve the next-step separation: this change neither creates the
  authorization card nor modifies, reviews, copies or publishes I4.
- Touch only OpenSpec workflow artifacts, synced decision documentation and
  board metadata; do not change protocol tools, Python manager/MCP code, Go
  product/tests, provider setup or runtime lab configuration.
