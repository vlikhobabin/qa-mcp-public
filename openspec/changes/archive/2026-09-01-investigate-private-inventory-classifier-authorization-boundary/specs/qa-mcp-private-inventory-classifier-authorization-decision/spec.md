## ADDED Requirements

### Requirement: Exact I4 is the bounded repeated-defect simplification
The investigation decision SHALL identify only
`oss-06-s4-r1-i4-classify-hidden-desktop-inventory-refusal-cause` at its exact
authorization-time `3.inprogress` path as the bounded successor. It MUST retain
`Repeated defect class: yes` and MUST NOT convert the lineage signal into a
prose or global waiver.

#### Scenario: Existing private classifier shape is selected
- **WHEN** the investigation compares exact I4's required successor shape with
  the published I3 decision and I6 private fenced seam
- **THEN** it selects the one behavior-neutral closed-vocabulary projection at
  the existing two private fences
- **AND** it excludes any successor that changes runtime behavior, adds an
  operation, expands the public surface or changes authority.

#### Scenario: Classifier boundary no longer holds
- **WHEN** the successor needs another Windows call, retry, fallback, wait,
  action, public route, wire field, marker derivation or more than its five
  private Go/test paths
- **THEN** this decision does not apply
- **AND** delivery requires a new split or investigation rather than extending
  the authorization.

### Requirement: Prepared authorization data binds one exact graph
The decision MUST prepare one six-field authorization object that binds the
published investigation path/id to the exact I4 successor path/id, sets
`production_loc_ceiling` to `301`, and sets
`allow_new_authority_or_wire_protocol` to `false`. It MUST require exact
reciprocal card links and a separate unchanged tracked `4.done` authorization
source before I4 review may resume.

#### Scenario: Separate authorization card is prepared
- **WHEN** this investigation has been independently reviewed and published in
  `4.done`
- **THEN** the next card may copy the exact prepared six-field object into its
  `Investigation authorization` field
- **AND** that card depends on this investigation and authorizes no other
  successor.

#### Scenario: I4 references the published source
- **WHEN** the separate exact authorization card is later published unchanged
  in `4.done`
- **THEN** I4 may reference only its exact two-field authorization path/id and
  depend on this investigation id
- **AND** any missing, stale, mismatched or additional field remains a
  fail-closed `investigation-required` result.

### Requirement: Authorization preserves the hostile offline verification floor
The decision MUST retain I4's 15-row hostile RED/GREEN matrix, closed-cause and
privacy checks, exact inventory/fence/admission/action counts, focused/full Go
tests and vet, Linux repository tests, deterministic non-executed Windows
cross-builds, strict OpenSpec, explicit scope and whitespace verification. The
authorization composition MUST NOT modify any I4 product or test blob.

#### Scenario: Authorization metadata is composed
- **WHEN** a later session prepares exact I4 for the dependency and
  authorization reference
- **THEN** it first establishes an at-most-five-path payload, exact blob
  identities and successful completion of the full required verification floor
- **AND** after metadata composition it proves those blobs unchanged, reruns
  deterministic preflight and obtains a fresh independent review before
  publication.

#### Scenario: Evidence floor would be weakened
- **WHEN** a future authorization omits a hostile row, privacy/call-count
  invariant, required offline suite, cross-build, scope or whitespace check
- **THEN** it does not satisfy this decision
- **AND** I4 remains blocked from review-gated publication.

### Requirement: Investigation grants no implementation or runtime authority
This investigation MUST change only its card, OpenSpec decision artifacts,
synced capability and board metadata. It MUST NOT copy or alter I4, create the
authorization card, run Windows or 1C, access a live endpoint or target, use
SSH, contact historical-user, or authorize any runtime action.

#### Scenario: Investigation is delivered
- **WHEN** the decision reaches review and publication
- **THEN** the tracked payload contains no product or test source change and no
  runtime evidence
- **AND** I4 remains blocked until the separately published authorization
  source satisfies the exact machine contract.
