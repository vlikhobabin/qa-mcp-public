# Единый локальный runtime ChangeRail

Этот комплект содержит общий native runtime. Версия кандидата `2.0.0-rc.3`
объединяет lifecycle OpenSpec, проверяемые доказательства, независимое ревью и
возобновление доставки. Это предварительная версия для испытаний перед стабильным выпуском 2.0.0.

Проекты используют установленную runtime-копию или явно подключённый общий
checkout через симлинки. В режиме разработки доступны также общие тесты.
Настройки находятся отдельно в `.changerail/profile.toml`; установщик их не
перезаписывает. Project root определяет Git, board и evidence, source root —
общий код. Каждая доставка сохраняет фактическую идентичность кода.

## Контракт

- Новое исполнение: только `openspec-v1`, одна карточка и один native change.
- OpenSpec владеет proposal, delta specs, design и tasks. Runner владеет
  сессиями, board, evidence, review, archive, финальными проверками и публикацией.
- Время и размер — наблюдения. Максимум два независимых ревью, включая ремонт
  после NO-GO и неудачной финальной проверки. Продолжение после archive остаётся
  в том же цикле и потоке ревью; resume не обнуляет счётчики.
- Старые записи доступны только для чтения. Установка нового runtime не даёт
  права продолжать старый frozen run по изменённому контракту.
- У каждого критерия приёмки есть ID и план evidence: предусловие, действие,
  ожидаемый результат, метод и этап проверки. Доказательства связываются с
  фактическими байтами, результатом команды, ролью и текущим payload.
- Неизменённую неудачную или прерванную проверку нельзя автоматически повторять.
  Незавершённая попытка и конкурирующий проверяющий блокируют новое исполнение.
- По умолчанию потерявшие актуальность проверки исполняются повторно.
  Переиспользование включается явно для локальных детерминированных проверок
  с полным объявленным набором зависимостей. Runtime и изменяемые внешние
  сервисы этим механизмом не доказываются.

## Границы

`scripts/changerail/` содержит одинаковое ядро во всех проектах.
`openspec_adapter.py` и native workflow связывают его с локальным OpenSpec;
`adapters/codex.py` строит вызов локального CLI, `adapters/pytest.py` проверяет
результаты конкретных тестов. Runtime evidence использует типизированные
ссылки на target, session, authorization, preflight и recovery; проект задаёт
требования к этим наблюдениям в плане evidence и своих инструкциях.

Профиль задаёт команды проверок, model routes, локальный launcher и проектную
политику. Доменные команды и credentials не входят в ядро. Новые форматы тестовых
результатов добавляются адаптерами с общими проверками ownership/freshness,
а не копированием и изменением runner в каждом проекте.

## Установка и обновление

Интерфейс сборки, проверки, первичного принятия исходников и установки:

```sh
python3 distribution.py --help
```

Первичное принятие существующего форка требует явного списка заменяемых файлов
и их хешей. Последующие обновления проверяют установленный lock и отказывают
при локальном изменении ядра. Проектные настройки и посторонние файлы сохраняются.
Незавершённый запуск требует отдельного решения о сохранении его как истории;
проверка установки не переписывает run receipts и не выдаёт право на resume.

Начальный профиль и карточка находятся в `tools/changerail/templates/`
относительно корня установленного проекта. Команды проверок нужно
заменить на реальные команды проекта до первой доставки. Требуются Python 3.11+,
Git, jsonschema, локальный Codex launcher и Node.js, совместимый с закреплённым
OpenSpec 1.3.1. Установка зависимостей OpenSpec выполняется явно; обычные команды
не скачивают пакеты и не используют глобальный fallback.

## Проверка изменений runtime

Тесты инструмента находятся в `tools/changerail/tests/` исходного
репозитория ChangeRail. Тесты, фикстуры и их launcher не входят в устанавливаемый
архив. Проекты используют готовый runtime; их CI не запускает тесты ChangeRail.
При установке достаточно проверки хешей и `./bin/chrl wiring` для подключения.
Интеграционные сценарии в исходном репозитории используют временные Git-репозитории,
локальный OpenSpec и подставленные ответы модели. Это не доказательство реальной
модельной доставки или поведения конкретного runtime-провайдера.

Исправление делается в общем исходнике, в том числе через ссылку потребителя,
и проверяется затронутой регрессией. Подключённые проекты сразу видят новую версию;
для runtime-копий собирается и устанавливается новый архив.
Опубликованный архив идентифицируется тегом, SHA-256 и source commit/tree
из `release-provenance.json`. Ветка `main` и shared checkout могут содержать
более новый код; одинаковая версия не гарантирует одинаковые байты.

## Дополнительные проверки

Обязательные дополнительные регрессии можно задать правилами `[[targeted]]`:
`paths` содержит glob-шаблоны путей, `commands` — команды проверок. Совпадение
с добавленным, изменённым или удалённым путём добавляет команды перед ревью,
сохраняя обязательные проверки профиля. При переименовании учитываются оба пути.
Эти правила не заменяют финальный floor и не предоставляют право reuse.

## Другие форматы тестовых результатов

По умолчанию используется строгий pytest parser. Другой проект может указать
`[adapters.tests] module = ".changerail/adapters/test_results.py"`.
Этот доверенный проектный модуль определяет
`parse_results(log, command_identity, target)` и возвращает отображение
`source_file::selector -> (start_byte, end_byte)` только для фактически
пройденных тестов. Код адаптера участвует в frozen process identity.
Общее ядро продолжает проверять owner, текущий payload, hash исходного журнала,
конкретные выбранные узлы и before/action/after фрагменты исходника теста.
Изменение или неисправность адаптера не разрешает использовать старые результаты.

## Руководства

Расширенные runbooks находятся в исходном репозитории; runtime-архив их не
копирует в потребителя. Для этой версии используйте документы точного тега:

- [Первая установка и доставка](https://github.com/vlikhobabin/changerail/blob/v2.0.0-rc.3/docs/quickstart.md).
- [Эксплуатация и восстановление](https://github.com/vlikhobabin/changerail/blob/v2.0.0-rc.3/docs/operations.md).
- [Общий исходник](https://github.com/vlikhobabin/changerail/blob/v2.0.0-rc.3/docs/shared-source.md).
- [Полномочия запуска](https://github.com/vlikhobabin/changerail/blob/v2.0.0-rc.3/SECURITY.md).
- [Архив, контрольные суммы и происхождение](https://github.com/vlikhobabin/changerail/releases/tag/v2.0.0-rc.3).

Runner требует `main` с upstream и при успешной доставке выполняет commit и
push. `require_push=false` пропускает лишь проверку доступности remote в doctor.
Codex-адаптер передаёт `--dangerously-bypass-approvals-and-sandbox`; окружение
и полномочия launcher задаёт оператор до запуска.
